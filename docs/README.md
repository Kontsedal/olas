# The docs site

A [VitePress](https://vitepress.dev) site, built from this folder and from the repo's own docs. The site does not render this file.

```bash
pnpm docs:build     # build the packages, check the API reports, sync, build the site
pnpm docs:dev       # sync, then serve with hot reload (needs a prior `pnpm build && pnpm api:check`)
pnpm docs:preview   # serve the built site
```

## What is written here, and what is generated

Written here, and checked by `pnpm check:doc-snippets` like the other docs:
- `index.md`, the home page, whose hero is `.vitepress/theme/components/HomeHero.vue`;
- the guide pages in `guide/` that have no "Generated from" comment: what-is-olas, getting-started, concepts, queries, mutations, forms, ssr, testing and performance.

Generated by `scripts/docs-sync.mjs`, and gitignored:
- `guide/recipes.md`, `guide/plugins.md` and `guide/migration.md`, from `RECIPES.md`, `PLUGINS.md` and `MIGRATING.md`.
- `adapters/` and `packages/`, from the package READMEs.
- `reference/`, the API reference. `api-documenter` builds it from the doc model that `pnpm api:check` writes to `temp/api-model/`.

Edit a generated page at its source. The sync rewrites the source's relative links. A link to another synced doc becomes that page's route, and any other link points at the file on GitHub.

## The theme

`.vitepress/theme/` extends VitePress's default theme with the house palette, the Atkinson Hyperlegible fonts and three components that any page can use:

- `<TwoTrees />` draws the component tree beside the controller tree.
- `<FrameworkPicker />` and `<ForFramework name="react">` (or `vue`, `svelte`) show one framework's code. The reader's choice holds across pages. Leave a blank line inside each `ForFramework`, so its Markdown renders, and keep headings outside it.

`.wiki/decisions/docs-site.md` has the reasoning behind each choice.

## Deploying

`.github/workflows/docs.yml` builds the site on every pull request. It deploys to GitHub Pages only when someone runs it by hand with `deploy` ticked, which needs the workflow on `main` and Pages set to the GitHub Actions source. The site is served under `/olas/`, which is `base` in `.vitepress/config.mts`.

Until `docs.yml` reaches `main`, Pages serves the `gh-pages` branch, and a docs change goes live when the built site is pushed there by hand. `BACKLOG.md` has the switch back to the Actions deploy.
